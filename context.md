# Nextpress — Project Context

> Curated project-wide knowledge for agents. Read this first before exploring.
> Owner: Solutions Architect. Last updated: 2026-10-23.

## What this is

Nextpress: self-hostable WordPress-compatible CMS. TypeScript monorepo (pnpm workspaces).
Dev DB = PGlite (embedded postgres, `data/pglite`). Prod = Postgres in Docker.

## Repo map

- `server/` — Express + Hono API, entry `server/index.ts`. Routes in `server/routes/*.routes.ts`, mounted in `server/routes/index.ts` under `/api/*`.
- `client/` — React 19 dashboard (wouter, react-query, shadcn/radix, tailwind). Pages in `client/src/pages/`.
- `shared/` — Drizzle schema (`shared/schema.ts`), shared logic (`shared/import/wordpress/`), base model factory (`shared/create-models.ts`).
- `packages/sdk` — `@nextpress-org/sdk`, TS client covering users/media/posts/pages/etc.
- `packages/mcp` — MCP server over the SDK.
- `scripts/nextpress` — **the real shipped CLI** (bash, installed to `/usr/local/bin` by `install.sh`). Has DB access via `compose exec -T postgres psql/pg_dump`, app health via `compose exec app node -e fetch(...)`.

## Key architecture facts

- **One CLI.** The bash `scripts/nextpress` is the shipped command (install/upgrade/status/logs/restart/reload/uninstall/version/help). The legacy npm package `@nextpress-org/cli` was removed 2026-08-27.
- **Auth**: `requireAuth` = better-auth session cookie OR Bearer API key (`npk_live_…`). `requireSessionAuth` = cookie only. Scope enforcement in `server/middleware/api-key-scope-enforcer.ts` using `shared/api-key-scopes.ts` SCOPE_RULES. **Unmapped `/api/*` routes fail closed (require ALL scopes)** — new routes must add a scope rule.
- **Multi-site**: most content tables are `siteId`-scoped. `users`, `templates`, `themes`, `plugins`, `sessions` are global; each site picks its own theme (`sites.activeThemeId`). A site's address lives on `sites.site_url` (see 2026-10-10). Requests must name their site (or use their API key's); there is no silent default-site fallback. Categories/tags live inside `posts.other` jsonb, not separate tables.
- **Media is binary on disk** in `uploads/` (multer diskStorage, served at `/uploads`), `media` table holds metadata + relative `url`. Export/import handles files separately from DB rows.
- **Transfer module** (`server/transfer/` + `server/transfer-cli.ts` → `dist/transfer-cli.js`): data export/import engine. Factories `createTransferExporter`/`createTransferImporter` (DI over models — reusable by future `/api/transfer` routes). Format: JSON `{manifest, data}`; `.tar.gz` with `media/` binaries when `--with-media-files`. Upsert by UUID, modes overwrite (default)/skip. FK import order: users→sites→roles→userRoles→templates→pages→blogs→posts→comments→media→options; parent chains topo-sorted. `--site` matches site NAME or hostname (sites table has no slug column). Bash CLI `nextpress export|import` runs it via `compose exec -T app node dist/transfer-cli.js`, payload over stdout/stdin. `server/db.ts` logs go to **stderr** — stdout is payload-only, keep it that way. Runner must `await pool.end()` before exit (pg-pool holds sockets ~10s otherwise).
- **`sites` entity bundles 3 tables**: `data.sites = { sites, roles, userRoles }` (type `SiteEntityData`). Import writes them in FK order under one "sites" summary entry — by design, NOT a bug. `ExportData.sites` is `SiteEntityData`, not an array.
- **Schema requirement (export/import needs current schema)**: the engine reads columns added in migrations `0006_posts_version.sql` (`posts.version`), `0007_posts_menu_order.sql` (`posts.menu_order`), `0006_api_keys_site_required.sql` (`api_keys.site_id`), and `0002_better_auth_and_multi_site.sql` (`users.name`, `users.email_verified`, `users.display_username`); `options.site_id`/`media.site_id` added in `0006`/`0008`. On an install whose DB predates these, export fails with `column "X" does not exist`. Fix = run `nextpress upgrade` (applies pending migrations). A drifted DB with a broken drizzle journal can't be auto-migrated — needs manual idempotent `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` (see 2026-08-27 verification note).
- **WP import** (`server/routes/import.wordpress.routes.ts` + `shared/import/wordpress/`): dedup via `other.import = {source, domain, wpId}` map (`build-imported-wp-map.ts`); re-import updates instead of duplicates; `sideloadRemoteImage` (`server/utils/sideload-remote-image.ts`) writes remote images to `uploads/` + creates media rows. Rate limit 5/min, batch max 50.
- **DB backup** (distinct from transfer export): bash CLI `create_db_backup()` (pg_dump to `$INSTALL_DIR/backups/`) used pre-upgrade only.
- Base model (`shared/create-models.ts`): `findMany`, `findManyWhere`, `findById`, `count`, `create`, `update`, `delete`.

## Data model (main tables)

sites(root), users(global), roles+userRoles(site), pages(site, unique siteId+slug), posts(via blogId, other.categories/tags), blogs(site), comments(via post), media(site), templates(global), themes, plugins, options(site, unique siteId+name), apiKeys(site), sessions, authSessions/accounts/verifications(better-auth), previewTokens(site).
UUID PKs everywhere except sessions.sid.

## Conventions

- See `AGENTS.md` (source of truth): factories not classes, `safeTry`, named params `{ name, email }`, plain words over jargon, domain folders with barrel `index.ts`, no cross-domain barrel re-exports.
- UI work: read `docs/design-system.md` first.
- Boundaries: never start servers, no DB commands, no git, no `.env` — ask owner. Backups to `/backup` before >10-line changes; deletes go to `/trash`.

### 2026-10-28 — Popups looked broken: Tailwind 4 class names on Tailwind 3.4
- **Cause:** commit `e02e288` (2026-09-12) reinstalled all shadcn components from the `new-york-v4` registry, which is written for **Tailwind 4**. The app runs **Tailwind 3.4.17**, which silently drops what it doesn't know. 238 class names in `client/src/components/ui/` made no CSS: `outline-hidden` (so the browser's black focus box showed: the Cmd+K search field), `shadow-xs`, `rounded-xs`, `origin-(--radix-…)`, `w-(--sidebar-width)`, `max-h-(--radix-select-…)`, bare `data-open:` / `aria-invalid:` / `has-data-[…]:` variants, `p-0!` important, `pointer-coarse:`, and every opacity modifier on a theme colour (`hover:bg-primary/90`, `ring-ring/50`, `bg-accent/50`).
- **Fix 1, opacity:** theme colours are whole values in variables (`var(--primary)` holds a hex or `hsl()`), which Tailwind 3 can't split. `tailwind.config.ts` `allowOpacity` turns each `var(...)` colour into a function: an explicit `/90` becomes `color-mix(in srgb, var(--x) calc(.9 * 100%), transparent)`; plain `bg-primary` keeps the plain value. Checked by generating the whole stylesheet before and after: 0 existing rules changed, 70 dead ones started working. `shared/tailwind-theme.ts` stays plain strings because the colour pickers read it (`client/src/lib/tailwind-tokens.ts`, `shared/resolve-token-entry.ts`).
- **Fix 2, syntax:** every v4-only name in `components/ui` and `components/ai-elements` rewritten to its 3.4 spelling (`outline-none`, `shadow-sm`, `rounded-sm`, `origin-[var(--x)]`, `data-[open]:`, `aria-[invalid=true]:`, `has-[[data-x]]:`, `!p-0`, `[@media(pointer:coarse)]:`, `break-words`, `[field-sizing:content]`, `[&.border-b]:`).
- **The stacking trap:** v3 reads stacked variants right to left, v4 left to right. `[&>*]:focus-visible:z-10` means "a focused child" in v4 but "children of a focused parent" in v3. Those were rewritten by hand as one selector (`[&>*:focus-visible]:z-10`, `[&>[data-slot=select-value]]:flex`, `[&[data-variant=destructive]>svg]:…`, `[&>tr:last-child]:…`). Parent conditions plus a child target (`group-…:[&>svg]:…`, `[a&]:hover:…`) mean the same on both and were left.
- **Left as is (unused components):** container queries in `field.tsx` (`@md/field-group:`, no plugin), `animate-caret-blink` in `input-otp.tsx`. `@container/card-header` in `card.tsx` is a harmless no-op.
- **Checking it:** the scratch scripts that found this generate CSS with the repo config and list class names that produce none. Rebuild them if a component is reinstalled: postcss + tailwindcss with `content: [{ raw }]`, then collect class selectors with `postcss-selector-parser`.
- **Rule:** never reinstall shadcn components on Tailwind 3.4 without converting them, or upgrade Tailwind first (owner's call; v4 also renames `shadow-sm`→`shadow-xs`, `rounded-sm`→`rounded-xs` across the whole app).
- **Also:** "Pre-designed Blocks" left the dashboard sidebar (owner). The page stays, reached from the editor's Templates panel, Design menu and Back button; it's still the only place to create, edit or delete them. Docs setup "On their own address" now reads "On a separate address", without the certificate wording.

### 2026-10-28 — Forgotten password: a reset command (`intent-reset-password-2026-10-28.md`)
- **Why:** the owner was locked out of their local copy. The cause was the 2026-10-21 hand reset to a temporary password (entry below), which the owner didn't know. Every install had the same gap: no reset-by-email, and `nextpress reset` wipes everything. Before the command existed, the local password was set by hand once more (database backup in `backup/pglite-before-password-reset-20261028-054244`).
- **What:** `pnpm reset-password <email or username>` (local) and `nextpress reset-password <email or username> [--password-stdin]` (servers, piped into `compose exec -T app node dist/reset-password-cli.js <login>`). Core: `server/lib/accounts/reset-password.ts`. Runner: `server/reset-password-cli.ts` (a tsup entry). Docs: `content/nextpress-docs/self-hosting/forgot-password.md`. No web route, no migration, no sign-in change: installs that never run it see nothing new.
- **How it saves:** through Better Auth itself: `auth.$context` → `password.hash`, `internalAdapter.updatePassword`, `linkAccount` when there is no `credential` record yet (very old installs), then `deleteUserSessions` (signed out everywhere, owner-approved), then it reads the password back and checks it. Login lookup matches sign-in: `@` means email, otherwise username, both lowercased. The password only ever travels on standard input (hidden prompt, or the first line of a pipe), never in arguments. **Tradeoff (approved):** `internalAdapter` isn't documented public API. `server/test/reset-password.test.ts` (real sign-ins on the in-memory DB with real migrations) fails if an upgrade renames it.
- **Traps found while dry-running it on a copy of the dev DB:**
  - **Closing PGlite resets `process.exitCode` to 0.** Set the exit code *after* `closeDatabase()`. `server/transfer-cli.ts` sets it before; that only matters for dev PGlite runs and was left alone.
  - **Better Auth reads the database as soon as it loads** (trusted origins → `sites`). A script that stops early must `await auth.$context` before closing the DB, or the in-flight query dies with a wasm "null function" error.
  - **Hidden prompts:** use readline's line iterator with a muted output stream. A hand-rolled raw-mode reader dropped the second line when both lines arrived together (typing ahead, pasting).
  - **Bash CLI tests that might prompt** run under `setsid --wait`, so `/dev/tty` can't wait on whoever runs the tests (`server/test/nextpress-reset-password.test.ts`). `[ -r /dev/tty ]` passes even with no terminal; actually opening it is the real check.
- **Replaces** the "changing a password in the live dev database" hand recipe below: stop `pn dev`, then `pnpm reset-password <login>`.

### 2026-10-22 — First real assistant run (MiniCPM via modelbest): a bad step must not end the run

### 2026-10-21 — Dev-server dependency pre-bundling (the "no export named getContext" trap)
- **Symptom:** the page builder and assistant showed `[plugin:runtime-error-plugin] The requested module …/@vercel/oidc/dist/index-browser.js does not provide an export named 'getContext'`. Later the same shape for `style-to-js/cjs/index.js` (no default export).
- **Why:** `vite.config.ts` runs with `optimizeDeps.noDiscovery: true` (turned on to stop mid-session re-optimisation from loading a second React copy). Only the hand-written `include` list is pre-bundled; anything else in `node_modules` is served raw. CommonJS packages cannot be imported by the browser that way — named exports are invisible.
- **The pnpm trap:** you cannot fix it by adding `"@vercel/oidc"` to `include` — pnpm keeps transitive packages under the parent, so Vite cannot resolve that name from the repo root and silently logs `Failed to resolve dependency: …` and drops the entry. Include the **root-resolvable entry point** instead (`ai`, `@ai-sdk/react`, `streamdown`); esbuild then inlines the CommonJS packages inside them.
- **`vite.config.ts` is read once at boot:** `server/setup-vite.ts` passes `configFile: false`, so Vite never watches it. Any config change needs a full dev-server restart (Ctrl-C then `pnpm dev`); the browser hash otherwise stays the same and the change looks like it "did nothing".
- **Checking a config change without touching the running server:** create a throwaway Vite server in a script with the same config plus `cacheDir: '/tmp/…'`, call `transformRequest('/src/main.tsx')` to force pre-bundling, then inspect the transformed import URLs — a raw `/@fs/…/node_modules/…` import means it is still unbundled.
- **Verifying in a browser:** `agent-browser --session <name>` — open `/admin/login`, fill `input[name=username]` / `input[name=password]`, submit, then `errors`, `console`, and `network requests` show whether a module error is gone and whether raw CJS (`/cjs/`, `@vercel/oidc`) is still requested.

## Hidden-tab flex bug (2026-09-12)

- Symptom: builder sidebar (tabbed shell, <1280px) scroll area clipped at ~half height; block library unreachable below the fold.
- Root cause: `BuilderSidebar` puts `flex` (display) on `TabsContent`. Radix keeps inactive tab content mounted with the `hidden` attribute, whose UA `display:none` is ALWAYS beaten by author display classes — so the hidden Settings tab split the column 50/50 with the active Blocks tab. Pure CSS chain (flex/min-h-0/h-full) was provably sound; the bug only shows in the Radix DOM.
- Fix: `data-[state=inactive]:hidden` added to the base `TabsContent` in `ui/tabs.tsx` — author display classes can no longer resurrect hidden tabs anywhere in the app (specificity: `[data-state=inactive][class]` beats `.flex`). Verified live at 1222×659: tab content 205→434px, viewport scrollable (4606px content), wide rail unaffected.
- Gotcha for future UI: never rely on the `hidden` attribute alone when adding `display:*` classes to Radix primitives that keep content mounted (Tabs Content, Accordion Content with forceMount, Dialog non-modal siblings).
- Debug workflow that cracked it: agent-browser `set viewport 1222 659` → live `getBoundingClientRect` walk of the chain → compare both `TabsContent` computed displays. Dev server was on :5000 (SPA fallback returns HTML 200 for unknown /api paths — check response BODY content-type when probing, status alone lies).
